# CLAUDE.md

Guidance for Claude Code (or any future contributor) working in this repo.

## What this is

GameTinder — a Tinder-style swipe UI for discovering Steam games, backed by SteamSpy and the
Steam Store API. Runs three ways from one shared frontend:

1. **Web/LAN** — `app.py` (Flask) serves `templates/index.html`, proxying SteamSpy/Steam so the
   browser never needs to talk to those APIs directly.
2. **Android app** — `mobile/` wraps a static copy of the same frontend in Capacitor, calling
   SteamSpy/Steam directly from the device (no server needed at all).
3. Both modes share one HTML file's logic — see "Dual-mode fetch" below.

## Architecture

- `app.py` — Flask backend, two routes only:
  - `/games?page=N` — page 0 proxies SteamSpy `top100in2weeks`; page N>0 proxies
    `request=all&page=N-1`. This is how the deck goes past the initial 100 games — it just keeps
    paging SteamSpy's `all` endpoint.
  - `/game/<appid>` — proxies Steam Store `appdetails`, extracts description/genres/categories/screenshots.
  - Binds to `0.0.0.0:5000` so it's reachable from other devices on the LAN.
- `templates/index.html` — the entire frontend. No build step, no framework, no bundler.
  Three.js is NOT used (that was tried and removed — see "Design history" below). The animated
  background is a hand-rolled Canvas 2D contour map (Perlin noise + marching squares), not an
  image or library.
- `mobile/` — Capacitor wrapper around a **copy** of `templates/index.html` (see below).

## Dual-mode fetch (important — read before touching networking code)

SteamSpy and the Steam Store API **do not send CORS headers**, so a plain browser `fetch()` from
a different origin (e.g. the Capacitor app) would be blocked. The frontend detects its
environment and branches:

```js
const isNative = !!(window.Capacitor && window.Capacitor.isNativePlatform && window.Capacitor.isNativePlatform());
```

- `isNative === false` (normal browser, LAN use) → calls `/games` and `/game/<appid>` on the
  Flask backend, which does the proxying server-side (no CORS issue since it's server-to-server).
- `isNative === true` (inside the Capacitor app) → calls `steamspy.com` / `store.steampowered.com`
  directly. This only works because `capacitor.config.json` has `CapacitorHttp.enabled: true`,
  which makes Capacitor route `fetch()` through a **native** HTTP client instead of the WebView's
  own networking stack — native requests aren't subject to browser CORS enforcement at all.

If you ever remove `CapacitorHttp.enabled`, the native branch will start failing silently with
network errors. If you ever add a *new* external API call, it needs the same `isNative` branch
treatment (see `fetchGamesPage` / `fetchGameDetails` in `templates/index.html`) unless that API
sends `Access-Control-Allow-Origin`.

## mobile/ — keeping it in sync (manual, no build step wires this up)

`mobile/www/index.html` is a **plain copy** of `templates/index.html`, not a symlink and not
generated by any script. **Whenever you change `templates/index.html`, copy it again:**

```bash
cp templates/index.html mobile/www/index.html
cd mobile && npx cap sync android
```

Skipping this means the web app and the Android app silently drift apart.

## Building the Android APK

Everything needed to build lives in two places, both intentionally kept out of git
(see `.gitignore`):

- `.android-toolchain/` — a **portable, self-contained** JDK 21 + Android SDK (cmdline-tools,
  platform-tools, `platforms;android-34`, `build-tools;34.0.0`). Nothing here touches the system
  PATH, registry, or global env vars — it's referenced only via:
  - `mobile/android/local.properties` → `sdk.dir=.../.android-toolchain/sdk`
  - `mobile/android/gradle.properties` → `org.gradle.java.home=.../.android-toolchain/jdk21`
- `mobile/node_modules/` — Capacitor CLI/core/android packages (`npm install` in `mobile/`).

**Capacitor 8 requires JDK 21** (not 17) for the `capacitor-android` module's Gradle build —
if you ever see `invalid source release: 21`, the JDK pointed to by `gradle.properties` is too old.

To rebuild after a frontend change:

```bash
cp templates/index.html mobile/www/index.html
cd mobile && npx cap sync android
cd android && ./gradlew.bat assembleDebug --console=plain
cp app/build/outputs/apk/debug/app-debug.apk ../../GameTinder.apk
```

If `.android-toolchain/` has been deleted to reclaim disk space (it's ~1.1GB), it needs to be
recreated before this will work — see git history / prior session notes for the exact
JDK 21 (Adoptium/Temurin) and Android cmdline-tools download URLs, or just re-download the
latest versions of each (a "command line tools only" package from
https://developer.android.com/studio, plus a Temurin 21 JDK zip from Adoptium) and re-extract
into `.android-toolchain/jdk21` and `.android-toolchain/sdk` respectively, then re-run
`sdkmanager --licenses` and install `platform-tools platforms;android-34 build-tools;34.0.0`.

A stray Gradle daemon can hold a file lock on the JDK folder if you try to swap JDK versions —
run `./gradlew.bat --stop` (or kill the `java.exe` process running from that JDK path) before
deleting/replacing a JDK.

## Conventions / things that bit us before

- **Don't add server-side state.** The Flask backend is a pure proxy with no database, no
  sessions, no secrets. Keep it that way — it's what makes the Capacitor on-device mode possible
  (nothing to bundle or re-host).
- **`liked` list persistence + no-repeat**: liked games are saved to `localStorage`
  (`gametinder_liked`) and their appids are kept in a `likedAppids` Set that filters every future
  page fetch, so a liked game never reappears — even across reloads/relaunches.
- **Pagination dedup**: `seenAppids` prevents the same game showing twice within a session as
  more SteamSpy pages get pulled in.
- **The card body must stay independently scrollable.** Expanding "+ More details" or paging
  through screenshots can make content taller than the card. `.card-body` has its own
  `overflow-y: auto` for exactly this reason — don't let card content escape without a way to
  scroll to it, that was a real bug once.
- **Currency**: SteamSpy's `price` field is in **US cents**, not any other currency. `formatPrice()`
  divides by 100 and prefixes `$`. Don't reintroduce a `₹` or other symbol without also fixing the
  currency assumption.
- **Design system**: minimal dark theme, Poppins font (bold weights), rounded corners
  everywhere, one violet accent color (`--accent`) used sparingly (price tag, rating bar, the
  "Yah" button, the logo highlight) — everything else is grayscale. Don't reintroduce multiple
  accent colors (an earlier green/red/amber scheme was explicitly rejected as looking "like a
  medical/hospital app").

## Design history (context, not instructions)

- The background was originally a Three.js animated grid + wireframe shapes, replaced with the
  current from-scratch Canvas 2D topographic contour animation (Perlin noise + marching squares)
  when the whole UI was redone in the current minimal dark theme.
- An earlier CRT/terminal retro theme (green-on-black, scanlines, VT323 font) was fully replaced
  by the current minimal dark + bold + rounded theme — don't reintroduce CRT/glow effects unless
  asked.

## Testing

There's no test suite. Verify changes with a real run:

```bash
python app.py
```

then check in a browser at `http://127.0.0.1:5000`. The `browser-automation` skill (headless
Playwright/patchright) is the fast way to check for console errors and inspect rendered state
without asking the user to look at a screen — used throughout this project's history for exactly
that.
